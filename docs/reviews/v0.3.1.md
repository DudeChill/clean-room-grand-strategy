# Release review v0.3.1

Patch release. It exists because v0.3.0's published tarball was packaged after an
in-flight agent edit landed, so the artifact and the tagged source disagreed. Nothing
in v0.3.0's *feature set* was wrong; the process was, and the fix is a release cut from
one verified tree.

## What changed

* **AI naval invasion staging**, the code that arrived unverified in v0.3.0, is now
  tested and correct:
  * the naval layer commits the army (`OrderKind::NavalInvasion`) before marching it,
    so the army layer stops pulling staged divisions back to the front;
  * every division that is not in the port is marched there each run (previously
    staging stopped once one division arrived), and any division marching elsewhere is
    redirected;
  * armies whose divisions are fighting are not chosen for a landing, because the
    crossing waits for the whole army and an engaged division cannot be pulled out;
  * the invasion launches only when the army has actually gathered.
* New regression test `ai_stages_an_inland_army_at_a_port_before_invading` drives the
  real tick loop: an inland army is committed, staged, held in the port (the test
  fails if a staged division is pulled back out), and the invasion is launched, with
  the auditor clean.
* `NAV-011` records the one remaining race (an engaged division assigned to the army
  before commitment can still stall the gather step) with its reproduction.
