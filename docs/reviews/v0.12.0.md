# Release review v0.12.0

Milestone: **Windows 10/11 build** plus a **one-click start** on both platforms.

## What is new

* **Portable networking**: every socket call goes through `src/core/socket_compat.h`, which
  holds each platform difference in one place — Winsock against POSIX, `SOCKET` against
  `int`, `SD_BOTH` against `SHUT_RDWR`, `WSAGetLastError` against `errno`,
  `ioctlsocket` against `fcntl`, a `select`-based wait that retries on `EINTR`, send/recv
  length types, `SO_SNDTIMEO` in milliseconds against a `timeval`, and `socklen_t`. The
  browser server and the multiplayer transport both use it; nothing else in the engine
  touches a socket.
* **Two real Windows bugs fixed** that a POSIX-only machine would never have shown:
  `ShellExecuteA` needs `<shellapi.h>` (which `windows.h` skips under
  `WIN32_LEAN_AND_MEAN`), and `if (client < 0)` after `accept` is dead code on Windows
  because `SOCKET` is unsigned — it now compares against the invalid handle.
* **One-click start**: `--play` picks a free port from 8080, prints a short banner, opens
  the default browser *without blocking*, and hands the player a country — with no
  `--player` it now takes the first living country of the scenario instead of silently
  putting a double-click into observer mode. `play.bat`, `play.sh` and `START_HERE.md` wrap
  it; the Linux tarball ships the launcher and the prebuilt binary.
* **Windows build in CI**: `.github/workflows/windows.yml` builds on `windows-latest` with
  MSVC (Release), runs the unit tests, zips `game.exe` with `data/`, `web/`, `play.bat`,
  `START_HERE.md`, `README.md` and `LICENSE`, keeps the zip as a build artifact and attaches
  it to the release for the tag.

## Honest limits of this release

* No Windows toolchain exists on the machine this was developed on (no mingw, no wine, no
  passwordless `sudo`), so **the Windows binary's execution is not verified locally**: it is
  compiled and unit-tested by CI, its archive contents are verified here, and `play.bat` was
  reviewed line by line rather than executed. Everything else in this review was run here.
* Windows support is *new*: the portability layer is covered by the Linux suite (which
  exercises the same code paths through the compat header), not by a Windows test matrix.

## Known gaps (tracked, not hidden)

* MINORs: **MOD-004** (mods cannot override the scenario/map), **ECON-004** (the AI piles up
  unsupported gear), **AI-014** (factory assignments follow pre-loss control counts).
* Known differences: no party-support vector (ideology operations apply as war support);
  counter-intelligence reads agency upgrades only.
* Full list in `docs/DISCREPANCIES.md`; the release gate now refuses to pass while any
  OPEN BLOCKER/MAJOR exists.
